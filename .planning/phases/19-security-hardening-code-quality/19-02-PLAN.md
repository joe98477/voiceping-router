    1. In `src/server/index.ts`, audit every HTTP endpoint in the `createServer` callback. For each endpoint, add a comment block documenting its security status. The audit should verify:

       - `/dev/seed-test-data` (POST) — Dev-only, guarded by `NODE_ENV !== 'production'`. Add comment: `// SECURITY AUDIT: Dev-only - guarded by NODE_ENV check, disabled in production`
       - `/test` (GET) — Dev-only, guarded by `NODE_ENV !== 'production'`. Add comment: `// SECURITY AUDIT: Dev-only - guarded by NODE_ENV check, disabled in production`
       - `/test/pttDemo.js` (GET) — Dev-only, same guard. Same comment pattern.
       - `/test/phase2` (GET) — Dev-only, same guard. Same comment pattern.
       - `/test/phase2.js` (GET) — Dev-only, same guard. Same comment pattern.
       - WebSocket `/ws` — Authenticated via JWT in `verifyClient`. Already secure.
       - Default (catch-all) — Returns 404. Confirm no auth bypass.

    2. Verify in `src/server/signaling/handlers.ts` that ALL signaling message handlers check channel authorization before accessing channel resources. Review each handler method for:
       - `handleJoinChannel`: Must check `ctx.authorizedChannels.has(channelId)` before joining
       - `handleCreateTransport`: Must validate user is in the requested channel
       - `handleProduce`: Must validate user is in channel and has PTT rights
       - `handlePttStart`/`handlePttStop`: Must validate channel membership
       - Admin handlers (FORCE_DISCONNECT, BAN_USER, UNBAN_USER): Must check admin/dispatch role
       - Location handlers: Must validate authenticated user
       Add a `// SECURITY AUDIT: Verified` comment at the top of `handlers.ts` summarizing the findings.

    **WebRTC DTLS Verification:**

    3. In `MediasoupClient.kt`, add DTLS parameter validation in both `createSendTransport` and `createRecvTransport` methods. After receiving the CREATE_TRANSPORT response from the server, before creating the transport with mediasoup-client:
       - Log the DTLS fingerprints count: `Log.d(TAG, "DTLS fingerprints received: ${dtlsFingerprints.size}")`
       - If dtlsParameters or fingerprints are missing/empty in the response, log a warning (not a crash — mediasoup enforces DTLS internally): `Log.w(TAG, "Warning: DTLS parameters missing in transport response")`

    4. In `src/server/signaling/handlers.ts`, in the `handleCreateTransport` handler (or wherever transports are created), add logging after transport creation to confirm DTLS state:
       - `logger.info(\`Transport ${transport.id} created with DTLS state: ${transport.dtlsState}\`)`
       - This confirms DTLS is being negotiated for every transport.

    **npm audit:**

    5. Run `npm audit --production` and capture results. If any CRITICAL or HIGH vulnerabilities are found in production dependencies, attempt to fix with `npm audit fix` (patch/minor only per user decision). Document results.
