    Create `web-ui/src/context/LocationContext.jsx` following the pattern established in `ChannelContext.jsx`:

    **LocationContext API:**
    - `locations` — `Map<userId, LocationPosition>` where LocationPosition is `{ userId, userName, latitude, longitude, accuracy, speed, heading, motionState, timestamp, batteryPercentage, powerSaveMode, networkType, lowBattery, isStale, isConnected }`
    - `updateLocation(userId, position)` — Update single location from LOCATION_BROADCAST. Uses `useCallback`. Creates new Map from prev, sets the entry. Also performs eager stale cleanup: iterate entries, delete any where `(Date.now() - new Date(entry.timestamp).getTime()) > 60 * 60 * 1000` (1 hour).
    - `setAllLocations(positions)` — Bulk set from LOCATION_QUERY response. Takes array of position objects, creates new Map from them. Used for initial load.
    - `mergeLocations(positions)` — Merge positions into existing Map (for reconnect — preserves existing markers, merges fresh data). Iterates positions array, sets each into new Map created from prev.
    - `removeLocation(userId)` — Remove single location entry.
    - `clearLocations()` — Clear all locations (called on event switch).

    **LocationProvider component:**
    - Props: `children`, `eventId`
    - State: `const [locations, setLocations] = useState(new Map())`
    - Clear locations when eventId changes: `useEffect(() => { clearLocations(); }, [eventId, clearLocations])`
    - All update functions wrapped in `useCallback` for stable references
    - Provider value object memoized or constructed carefully to avoid unnecessary re-renders

    **useLocations hook:**
    - Standard pattern: `useContext(LocationContext)` with error if null ("useLocations must be used within LocationProvider")
    - Returns `{ locations, updateLocation, setAllLocations, mergeLocations, removeLocation, clearLocations }`

    **Important:** This context is NOT wired to WebSocket yet (that's Plan 02). This task only creates the state container.
