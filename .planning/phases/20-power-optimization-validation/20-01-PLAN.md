    - `@Singleton` class with `@Inject constructor(@ApplicationContext context: Context)`
    - Acquire `PowerManager.PARTIAL_WAKE_LOCK` with tag `"VoicePing::AudioMonitoring"`
    - Use `Handler(Looper.getMainLooper())` with `postDelayed` for timeout-based release
    - `wakeLockTimeoutMs: Long` property (default 300_000L), set from server config on auth
    - `fun acquire()`: Acquire wake lock if not held, reset timeout. Log acquisition.
    - `fun resetTimeout()`: Cancel existing delayed release, schedule new one at `wakeLockTimeoutMs`. This is called on every audio activity event to keep the wake lock alive.
    - `fun releaseImmediate()`: Cancel timeout, release wake lock if held. Used on disconnectAll.
    - `fun setTimeoutFromServer(seconds: Long)`: Set `wakeLockTimeoutMs = seconds * 1000L`. Called when auth response received. If server provides 0 or negative, fallback to 300_000L.
    - `var onWakeLockReleased: (() -> Unit)? = null` callback for coordinating with LocationManager (location interval doubling)
    - `var onWakeLockAcquired: (() -> Unit)? = null` callback for coordinating with LocationManager (location recovery)
    - Expose `val isHeld: Boolean` property checking `wakeLock.isHeld`
    - Expose `_wakeLockActive` as `MutableStateFlow<Boolean>(false)` and public `wakeLockActive: StateFlow<Boolean>`. Update on acquire/release.
    - CRITICAL: Minimum hold pattern — after reacquisition via `acquire()`, the timeout resets to full `wakeLockTimeoutMs`, preventing rapid toggling.
    - CRITICAL: Always check `wakeLock.isHeld` before release to avoid `WakeLock under-locked` exception.

                delay(1000L) // Check again in 1s
                continue
