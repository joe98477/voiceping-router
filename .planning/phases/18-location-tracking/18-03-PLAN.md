    3. Update LocationManager.kt to add WebSocket transmission and offline queue:

       - Add offline queue:
         ```kotlin
         private val offlineQueue = ArrayDeque<LocationUpdate>(50)
         private val maxQueueSize = 50
         ```
       - Add `private fun sendLocationUpdate(update: LocationUpdate)` method:
         - If `signalingClient.connectionState.value == ConnectionState.CONNECTED`:
           - First call `flushOfflineQueue()` if queue not empty
           - Then send individual update: `signalingClient.send(SignalingType.LOCATION_UPDATE, update.toJsonObject())`
           - Note: Use the existing `send()` method pattern from SignalingClient (fire-and-forget, no request/response needed)
         - Else (disconnected):
           - If `offlineQueue.size >= maxQueueSize` → `offlineQueue.removeFirst()` (drop oldest)
           - `offlineQueue.addLast(update)`
       - Add `private fun flushOfflineQueue()` method:
         - If queue empty → return
         - Create batch: `val batch = offlineQueue.toList()`
         - Clear queue: `offlineQueue.clear()`
         - Create JsonObject with "updates" array containing each update's toJsonObject()
         - Send as `SignalingType.LOCATION_BATCH`
       - Wire the `_locationUpdates` SharedFlow emission to call `sendLocationUpdate()`:
         - In the existing location update callback (from plan 01's startTracking), after emitting to SharedFlow, also call `sendLocationUpdate(locationUpdate)`
       - Add reconnect observer:
         - In `startTracking()`, launch a coroutine that collects `signalingClient.connectionState`:
           - When state transitions to CONNECTED, call `flushOfflineQueue()`
       - Expose current location for debug screen:
         ```kotlin
         private val _currentLocation = MutableStateFlow<LocationUpdate?>(null)
         val currentLocation: StateFlow<LocationUpdate?> = _currentLocation.asStateFlow()
         ```
         Update `_currentLocation.value` on each location callback (before deduplication — show ALL received locations, not just sent ones).

         Only call if not already tracking. The LocationManager's `startTracking()` should handle being called multiple times (idempotent — check `isTracking` flag).
