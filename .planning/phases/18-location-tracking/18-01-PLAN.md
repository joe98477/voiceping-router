<task type="auto">
  <name>Task 2: LocationTracker, MotionDetector, ActivityTransitionReceiver, and LocationManager</name>
  <files>

  <action>
    1. Create LocationTracker.kt — FusedLocationProviderClient wrapper:
       - `@Singleton` with `@Inject constructor(@ApplicationContext context: Context)`
       - Create `fusedLocationClient` via `LocationServices.getFusedLocationProviderClient(context)`
       - `startTracking(intervalMs: Long, priority: Int, onLocationUpdate: (Location) -> Unit)` method:
         - Build `LocationRequest.Builder(priority, intervalMs).setMinUpdateIntervalMillis(intervalMs / 2).build()`
         - Create `LocationCallback` that calls `onLocationUpdate` with `result.lastLocation`
         - Call `fusedLocationClient.requestLocationUpdates(locationRequest, callback, Looper.getMainLooper())`
         - Use `@SuppressLint("MissingPermission")` — caller (LocationManager) checks permission
       - `stopTracking()` — removes location updates and nulls callback
       - Log tag: "LocationTracker"

    2. Create MotionDetector.kt — ActivityTransition API wrapper:
       - `@Singleton` with `@Inject constructor(@ApplicationContext context: Context)`
       - `private val activityRecognitionClient = ActivityRecognition.getClient(context)`
       - `_motionState` as `MutableStateFlow<MotionState>(MotionState.UNKNOWN)` and expose `motionState: StateFlow<MotionState>`
       - `startMonitoring()` method:
         - Register transitions for: STILL enter, WALKING enter, IN_VEHICLE enter
         - Create PendingIntent for ActivityTransitionReceiver broadcast (FLAG_UPDATE_CURRENT or FLAG_MUTABLE)
         - Call `activityRecognitionClient.requestActivityTransitionUpdates(request, pendingIntent)`
         - Use `@SuppressLint("MissingPermission")` — caller checks permission
       - `stopMonitoring()` — remove activity transition updates
       - `updateMotionState(state: MotionState)` — public method called from ActivityTransitionReceiver
       - GPS displacement fallback fields:
         - `private var lastDisplacementLocation: Location? = null`
         - `private var consecutiveNoMovementCount = 0`
         - `fun checkDisplacementFallback(location: Location)` — if Activity Recognition unavailable, use GPS displacement:
           - Calculate distance via `Location.distanceBetween()`, if < 30m → increment counter, if counter >= 2 → set STILL
           - If >= 30m → reset counter, set WALKING
       - Log tag: "MotionDetector"

    3. Create ActivityTransitionReceiver.kt as BroadcastReceiver in service/ package:
       - `@AndroidEntryPoint` class
       - `override fun onReceive(context, intent)`:
         - Check `ActivityTransitionResult.hasResult(intent)`
         - Extract result, iterate `transitionEvents`
         - Map `DetectedActivity.STILL` → MotionState.STILL, `WALKING`/`RUNNING`/`ON_BICYCLE` → MotionState.WALKING, `IN_VEHICLE` → MotionState.DRIVING
         - NOTE: Since receiver is short-lived and MotionDetector is a singleton, use a companion object callback pattern or static reference. The simplest approach: MotionDetector exposes a companion `var instance: MotionDetector? = null` set during injection, and the receiver calls `MotionDetector.instance?.updateMotionState(state)`. This avoids Hilt complexity in BroadcastReceivers.
       - Register receiver in AndroidManifest.xml inside `<application>`:
         ```xml
         <receiver
             android:name=".service.ActivityTransitionReceiver"
             android:exported="false" />
         ```

    4. Create LocationManager.kt — coordinator singleton:
       - `@Singleton` with `@Inject constructor(@ApplicationContext context: Context, locationTracker: LocationTracker, motionDetector: MotionDetector)`
       - State fields:
         - `private var isTracking = false`
         - `private var lastSentLocation: Location? = null`
         - `private var lastSentTime: Long = 0`
         - `private val _locationUpdates = MutableSharedFlow<LocationUpdate>()` — expose as `SharedFlow` for plan 03 to collect
         - `private var activityRecognitionAvailable = true` — set false if startMonitoring fails
       - `startTracking()` method:
         - Check location permission via `ContextCompat.checkSelfPermission`
         - Start motion detector (catch failure → set `activityRecognitionAvailable = false`, fall back to GPS displacement)
         - Start location tracker with initial interval (60s walking default) and PRIORITY_BALANCED_POWER_ACCURACY
         - On each location update:
           - If activity recognition unavailable, call `motionDetector.checkDisplacementFallback(location)`
           - Check deduplication: `shouldSendLocation(location)` — skip if moved < 50m since last send
           - If should send: create `LocationUpdate` from Location (latitude, longitude, accuracy, speed, bearing, current motionState, ISO8601 timestamp via `java.time.Instant.now().toString()`)
           - Emit to `_locationUpdates` SharedFlow
           - Update `lastSentLocation` and `lastSentTime`
       - `stopTracking()` — stop tracker and detector
       - Observe `motionDetector.motionState` in a coroutine scope:
         - On motion state change, restart tracker with new interval:
           - STILL → 5 * 60 * 1000L (5 min)
           - WALKING → 60 * 1000L (60s)
           - DRIVING → 30 * 1000L (30s)
           - UNKNOWN → 60 * 1000L (60s)
         - Check battery level via BatteryManager:
           - `val batteryManager = context.getSystemService(Context.BATTERY_SERVICE) as BatteryManager`
           - `val batteryLevel = batteryManager.getIntProperty(BatteryManager.BATTERY_PROPERTY_CAPACITY)`
           - If < 20%: force interval to 5 min and priority to PRIORITY_LOW_POWER
       - `shouldSendLocation(newLocation: Location): Boolean`:
         - If `lastSentLocation == null` → true (first send)
         - Calculate distance via `Location.distanceBetween()`, return `distance >= 50f`
       - `fun requestPttTriggeredLocation()` — for PTT-triggered sends:
         - If `System.currentTimeMillis() - lastSentTime < 120_000` → skip (no update needed)
         - If battery < 20% → skip (suppress per user decision)
         - Otherwise force-emit current location from last known tracker position
       - Log tag: "LocationManager"
       - Use `CoroutineScope(SupervisorJob() + Dispatchers.IO)` for internal coroutines
  </action>
