  <action>
    **PermissionState.kt** — Create sealed class in domain/model/:
    ```
    sealed class PermissionState {
        data object Granted : PermissionState()
        data object Denied : PermissionState()
        data object PermanentlyDenied : PermissionState()
    }
    ```

    **PermissionManager.kt** — Create `@Singleton` class in data/permissions/ with `@Inject constructor(@ApplicationContext context: Context)`:

    1. **In-memory denial tracking** (resets on app restart per user decision):
       - `private val denialCounts = mutableMapOf<String, Int>()` — per-permission denial count
       - `private val hasRequested = mutableSetOf<String>()` — tracks if permission was requested before (for first-time vs permanent denial distinction)
       - `fun trackDenial(permission: String): Boolean` — increments count, returns true if count >= 2 (should redirect to Settings)
       - `fun markRequested(permission: String)` — adds to hasRequested set
       - `fun resetDenialCount(permission: String)` — removes from denialCounts (called when permission granted)

    2. **Permission status checks** (always-current via ContextCompat.checkSelfPermission):
       - `fun hasMicPermission(): Boolean` — checks RECORD_AUDIO
       - `fun hasLocationPermission(): Boolean` — checks ACCESS_COARSE_LOCATION (per research recommendation: start coarse)
       - `fun hasNotificationPermission(): Boolean` — checks POST_NOTIFICATIONS with Build.VERSION.SDK_INT >= TIRAMISU guard (returns true on < API 33)
       - `fun getPermissionState(activity: Activity, permission: String): PermissionState` — returns Granted/Denied/PermanentlyDenied using:
         - Granted if checkSelfPermission == GRANTED
         - PermanentlyDenied if denied AND shouldShowRequestPermissionRationale returns false AND hasRequested contains permission
         - Denied otherwise

    3. **Settings redirect**:
       - `fun shouldRedirectToSettings(permission: String): Boolean` — returns denialCounts[permission] >= 2
       - `fun openAppSettings(context: Context)` — launches Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS) with app package URI

    4. **Aggregate state for UI**:
       - `fun getMissingPermissions(): List<String>` — returns list of denied permission names (human-readable: "Microphone", "Location", "Notifications")
       - `fun getMissingPermissionCount(): Int`

    **SettingsRepository.kt** — Add first-launch education key to existing Keys object:
    - Add `val HAS_SHOWN_PERMISSION_EDUCATION = booleanPreferencesKey("has_shown_permission_education")` to Keys
    - Add `suspend fun setPermissionEducationShown()` — sets key to true
    - Add `fun hasShownPermissionEducation(): Flow<Boolean>` — maps key, defaults to false

    **Important:** Do NOT add ACCESS_COARSE_LOCATION to AndroidManifest.xml — that will be added in Phase 18 (Location Tracking). PermissionManager.hasLocationPermission() will simply return false until the manifest permission is added. This is correct because the education screen lists all three permissions for awareness, but location functionality is not implemented until Phase 18.
