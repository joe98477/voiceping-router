- Fixed all three issues

<context>
This is an ongoing debugging effort across multiple sessions. The core infrastructure (mediasoup SFU, WebSocket signaling, Android client) works at the signaling level. The issues have been around NAT traversal (TURN/ICE) and protocol mismatches between Android client and server.

Key architecture notes:
- mediasoup is ICE-lite (server provides host candidates only)
- coturn handles STUN/TURN relay for clients behind CGNAT
- Android uses crow-misia libmediasoup-android 0.21.0
- Web client uses mediasoup-client JS library
- Server runs in Docker Compose on remote host `connectvoice` (IP: 203.40.59.18)
- All Docker traffic routes through nginx on single internal IP

The `iceTransportsType = RELAY` fix is the key change — it forces the Android WebRTC peer connection to use TURN relay instead of attempting direct UDP to mediasoup ports (40000-40099). This avoids the CGNAT binding timeout that was causing ICE to fail after ~2 minutes.
</context>
