    **1. DispatchConsole.jsx — Add LocationProvider and WebSocket connection:**

    Import `LocationProvider` from `../context/LocationContext.jsx`.

    Create a dedicated WebSocket connection for location updates in DispatchConsole. This is separate from channel-specific ConnectionManager connections. The location WebSocket needs the router token for authentication.

    Add a `useEffect` that creates a WebSocket connection when `token` is available:
    ```
    const locationWsRef = useRef(null);

    useEffect(() => {
      if (!token) return;

      // Build WebSocket URL with token as sec-websocket-protocol (matching server auth pattern)
      const ws = new WebSocket(wsUrl, token);
      locationWsRef.current = ws;

      ws.onopen = () => { console.log('[LocationWS] Connected'); };
      ws.onerror = (e) => { console.error('[LocationWS] Error:', e); };
      ws.onclose = () => { console.log('[LocationWS] Disconnected'); locationWsRef.current = null; };

      return () => {
        ws.close();
        locationWsRef.current = null;
      };
    }, [token, wsUrl]);
    ```

    Wrap the map panel content area (and the channels panel) with `<LocationProvider eventId={eventId}>`. The LocationProvider should wrap BOTH panels so that location state is available regardless of which panel is visible. Place it inside the `dispatch-console__main-content` div, wrapping both `channels-panel` and `map-panel`.

    Compute `isMapVisible` based on layout state:
    - Desktop: `!isCollapsed` (map panel is visible when channels panel is not collapsed — actually the map panel is always visible on desktop; the collapse only affects channels panel width. Map is hidden only on mobile when channels tab is active.)
    - Mobile: `activeTab === 'map'`
    - Combined: use CSS media query breakpoint awareness or simply: on mobile (<1200px), `activeTab === 'map'`; on desktop, always true (map panel always mounted and visible).
    - Simplest correct approach: `isMapVisible = true` on desktop (map panel always rendered), `activeTab === 'map'` on mobile. Use `window.matchMedia('(min-width: 1200px)')` to detect. Or more simply, since both panels stay mounted (CSS visibility control per Phase 22), pass `isMapVisible` as a prop derived from: desktop always true OR mobile tab is map.

    **2. MapView.jsx — Add WebSocket listener, LOCATION_QUERY, and marker rendering:**

    Import `useLocations` from `../context/LocationContext.jsx`.

    Accept new props: `ws` (WebSocket instance), `isMapVisible` (boolean).

    **WebSocket LOCATION_BROADCAST listener** — add a `useEffect` that:
    - Guards: return early if `!ws || ws.readyState !== WebSocket.OPEN`
    - Creates named `handleMessage` function that parses JSON, checks `message.type === 'location-broadcast'`, extracts data, calls `updateLocation(data.userId, data)`
    - Adds listener: `ws.addEventListener('message', handleMessage)`
    - Returns cleanup: `ws.removeEventListener('message', handleMessage)`
    - Dependencies: `[ws, updateLocation]`

    **LOCATION_QUERY on map visibility** — add a `useEffect` that:
    - Uses `hasQueriedRef = useRef(false)` to track if query was sent
    - Guards: return early if `hasQueriedRef.current || !isMapVisible || !ws || ws.readyState !== WebSocket.OPEN`
    - Creates named `handleQueryResponse` function that parses JSON, checks for `message.type === 'channel-state'` (because `sendResponse` uses CHANNEL_STATE type) AND `message.data?.positions` to identify location query response. Alternatively check by correlating the message ID.
    - Better approach: Use correlation ID. Generate `queryId = 'loc-query-' + Date.now()`. Listen for response matching `message.id === queryId`. On match, call `setAllLocations(message.data.positions)` (or `mergeLocations` if locations already exist from broadcasts), set `hasQueriedRef.current = true`, remove the listener.
    - Send: `ws.send(JSON.stringify({ type: 'location-query', id: queryId }))`
    - Cleanup: remove response listener on unmount
    - Dependencies: `[ws, isMapVisible, setAllLocations, mergeLocations]`

    **NOTE on response type**: The server's `sendResponse` method sets `type: SignalingType.CHANNEL_STATE` as default. The response will have `type: 'channel-state'` but with `message.id` matching the query ID and `message.data.positions` array. Match on ID, not type.

    **Marker rendering** — add a `useEffect` that:
    - Gets `locations` from `useLocations()`
    - Maintains a `markersRef = useRef(new Map())` — Map<userId, L.Marker> for Leaflet marker instances
    - On every `locations` change:
      - For each entry in `locations`:
        - If marker exists in markersRef for this userId: call `marker.setLatLng([lat, lng])` (CSS transition handles animation). Update icon HTML if userName changed.
        - If no marker exists: create new marker with `L.divIcon` and `L.marker`, add to map, store in markersRef.
      - For markers in markersRef NOT in locations: remove from map (`map.removeLayer(marker)`), delete from markersRef.
    - Cleanup: remove all markers on unmount
    - Dependencies: `[locations]` (and map instance from mapRef)

    **DivIcon structure** for each marker:
    ```javascript
    L.divIcon({
      className: 'user-marker',
      html: `
        <div class="user-marker__label">${userName}</div>
        <div class="user-marker__pin">
          <div class="user-marker__icon">
            <svg viewBox="0 0 24 24" width="14" height="14" fill="white">
              <circle cx="12" cy="8" r="3.5"/>
              <path d="M12 14c-4.4 0-8 2-8 4.5V20h16v-1.5c0-2.5-3.6-4.5-8-4.5z"/>
            </svg>
          </div>
        </div>
      `,
      iconSize: [32, 40],
      iconAnchor: [16, 40],  // Bottom-center of pin tip
    })
    ```

    **Stale marker cleanup timer** — add a `useEffect`:
    - `setInterval` every 5 minutes
    - Iterate locations, check `(Date.now() - new Date(loc.timestamp).getTime()) > 60 * 60 * 1000`
    - Call `removeLocation(userId)` for stale entries
    - Return cleanup: `clearInterval(intervalId)`

    **Staggered batch updates** — when processing LOCATION_QUERY response with >5 positions, use staggered updates:
    ```javascript
    if (positions.length > 5) {
      positions.forEach((pos, index) => {
        setTimeout(() => updateLocation(pos.userId, pos), index * 50);
      });
    } else {
      mergeLocations(positions);
    }
    ```

    **Important safeguards:**
    - All `useEffect` hooks return cleanup functions
    - Named functions for event listeners (not inline arrows) — enables proper cleanup
    - Guard `mapRef.current` before accessing map instance
    - Guard `ws.readyState === WebSocket.OPEN` before sending
